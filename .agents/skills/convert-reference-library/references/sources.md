# 来源适配

所有来源均按实际正文识别内容：文件名可能是随意命名、旧名称或与正文无关的名称，只作来源定位，不作主题概括。同一文件可以同时包含背景知识、设定素材、文风技巧和环境协议等；逐项筛选，可拆为多个自足单元，不沿用文件边界作为知识类别或收录边界。

世界书：支持entries对象/数组，以及character_book.entries。用原UID或数组位置作为来源条目标识，comment/name/标题和key/keysecondary作为理解线索。依照SKILL.md的收录范围筛选，不要求全条目转换。enabled/disable不成为新库开关，也不单独决定取舍；确认被新版替代是排除理由之一，纯环境协议、无通用创作价值等同样可提出不收录建议。内容可能是道具、功法、创作规则、文风、生活背景或其他材料，不限定分类。原order/position/概率/递归只作维护背景，不写入正式资料。

混合条目示例：一条“拍卖会规则”同时包含竞价流程与“每轮输出 `<auction_status>`、更新酒馆变量”的要求时，只提取竞价流程及理解它所必需的条件；一条“文风要求”若含短句、意象和对白技巧，则保留这些指导，剔除末尾固定状态栏要求。纯粹的输出格式或插件控制条目不入库。保留/提取/排除建议仍先交用户审查。

本地文章/讨论串：保留文章标题、段落、引用关系及发言语境；来源网址、日期、作者记录在维护清单，避免当作搜索字段。帖子或评论不自动当已证实事实。没有授权的抓取、登录、网页采集和OCR不属于转换工具能力。

小说/长篇文本：先筛选有创作参考价值的章节、场景或完整段落，不要求整本收录；保留选中内容的叙事与表达，不改写成规则清单。不强拆表格和连贯例外。长文可以先列候选章节审查后逐章转换；检索用的向量切片由资料库模块另行处理。

来源工具只清点，不替代语义理解与用户审查。正式单元不是固定一条源条目，拆合映射写维护清单。
