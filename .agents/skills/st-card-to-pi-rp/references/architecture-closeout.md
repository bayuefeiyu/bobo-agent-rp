## 4. 本次收尾新发现

- 模块注册后的工作流 ID 已带所有者前缀，调用面校验再次拼接前缀导致合法模块调用被拒。改为使用规范化后的 ID；新卡真实 `card-context-library/export-context` 调用可完成。
- 打包 Web 过滤器先接受目录，导致 `web/test/` 被复制。修正为先排除测试目录；交付夹具断言产物无 Web／宿主 `.test.mjs`。本轮没有改变用户卡内模块自带测试的打包策略。
- 打包器原有独立 Pi 版本字面量改为读取统一开发声明，产物锁与声明有一致性断言。
- 启动器对缺失模型默认文件应返回校验错误，却先抛 ENOENT。改为保留缺失文件错误并继续收集；损坏文件也报告校验错误，不放宽有效性判断。
- ComfyUI profile 测试的正例没有创建必需 guide，Python 契约测试只读已经变薄的入口。分别补全隔离夹具和实际实现读取范围；没有削弱断言或更改业务协议。
- Python 未定义引用辅助检查把合法闭包参数误判为缺失全局名字，也会把某函数内部 import 错当成全局 import。改用标准库符号表；三项回归覆盖闭包、局部 import 和真正缺失 import。
- 未导入图像模块的新卡在聊天开始前仍显示 available。按实际模块存在性返回状态，交付测试验证无图像模块时不可用。
