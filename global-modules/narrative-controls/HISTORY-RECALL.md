# 历史原文回顾

正文模块自带的可选功能，默认关闭。它从当前有效历史正文建立切片向量索引，并在正文创作前自动交付相关历史原文。无需装配记忆或资料库模块；与记忆模块同时使用时，记忆提供整理后的信息，回顾补充具体对白、动作和叙述。

## 开启与配置

1. 在配置页的“历史回顾”保存 embedding 和 rerank 服务地址、模型和凭据，然后测试已保存服务。连接测试只发送合成短文。
2. 在正文模块的“历史原文回顾”开启功能。已有合格历史会后台补建；配置方案中的参数只初始化新会话，当前聊天使用正文面板的设置。
3. 在“历史索引维护”选择补建/恢复、重新编码或查看状态。配置页显示覆盖、保护轮次和任务进度。取消运行中的索引也可以使用工作流面板的取消控制。

开启后，历史片段发送给所选 embedding 服务；本轮查询及召回候选发送给 embedding/rerank 服务。凭据保存于宿主用户配置目录，不进入卡包或创作 Agent 工作区。

## 默认行为

- 入库 CD 为 3 个新满足条件的有效正文轮次。同轮重生成、失败重试不增加计数。
- 保护最近正文，默认跟随产生正文的前台工作流 `turnContext.recentCompleteTurns`；也可以选择固定轮数。CD 会形成短暂覆盖空档，缩短保护窗口可提前索引。
- 每轮分别聚合多个短自然段，目标 800 个 UTF-16 字符，最大 1200。长段按句子继续拆分，相邻片段最多重叠 120 字符，200 字符以内短尾尽量合并。不跨轮拼接。
- 只收录有效 assistant 正文及所选开场；不收录玩家输入、失败草稿、未采用候选和其他模块故事。
- 最近一次有效正文和当前玩家输入分别向量查询，每路召回最多 30 片，再合并做 rerank。超长查询保留开头及末尾，裁剪会写入用户诊断。
- 默认最多 6 项、6000 字符、同轮最多 2 项；允许更少或空结果。邻段补齐和重叠合并也计入预算，最终按轮次交付。
- 不向创作 Agent 暴露检索工具；只交付声明的历史原文文档。过去的状态、对白和猜测需按历史语境解释。
- 回顾最长 15 秒，服务或索引不可用时跳过回顾，正文继续。权限、模块打包和协议错误明确失败，不伪装成空结果。

## 来源、索引与恢复

原文仍由 conversation 集合负责。索引位于会话的 `derived/narrative-history/`，来源由消息 ID、revision 和内容指纹精确匹配；检索只接受当前执行允许读取的正文版本，且在 top-k 前排除废弃版本及创作节点已直接可见的正文。

手改、候选采用和后缀删除后，后续执行立即排除不匹配切片，新内容随后补建。旧执行仍使用其冻结的来源。缓存中的旧切片可以保留，但不会因此进入新视图。没有自动清理旧空间；索引总上限为 100000 片及 512MiB 原始向量，触及上限明确停止处理。

完整来源编码成功后才在 SQLite 事务中发布覆盖。失败来源保持待处理，可补建/恢复；重编码失败保留之前可用来源。后台任务每个服务请求和来源发布都有取消检查，关闭会取消在途操作。索引和查询在 worker 中执行，不阻塞 Web 主线程。

embedding 地址、模型、维度、前缀或空间版本变化后建立新空间；切片参数变化后使用新切片版本；仅 rerank 模型变化不重做 embedding。配置或凭据变化后需重新测试服务。

索引文件损坏会在状态中报告 `history_index_corrupt`，回顾暂时跳过；选择“重新编码”会保留损坏文件用于诊断，并从有效正文建立新的索引。

首版只实现 c（向量召回 + rerank）。`recallCandidates` 对应候选扫描，`selectCandidates` 使用可替换的选择函数，`composeExcerpts` 负责来源还原与交付预算，可扩展 a/b。真实模型质量需用真实游玩样本验证，离线合成服务测试只证明协议与生命周期。

## 开发与交付边界

仓库源模块与运行时模板的更新不传播到已安装卡或已有会话。新独立卡运行包携带历史索引及公共语义服务代码，无需仓库或资料库模块。旧卡与会话升级须单独明确目标；本功能不提供隐式迁移。

配置方案对 settings 集合中非首条记录使用 `moduleOverrides.<moduleId>.$records.<collectionId>.<recordId>`，普通旧配置仍作用于原先首条 settings 记录。
