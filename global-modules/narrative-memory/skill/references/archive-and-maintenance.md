# 归档、压缩与维护

## 两级归档

第一级和第二级获得相同的基础材料：世界观固定提示词、明确区分的早期参考剧情、本次归档剧情、来源捕获和所有完整目录。第二级另外获得第一级清单、模板、时间规则、摘要超限任务和统一变更格式。

第一级只输出客观Markdown清单：需要新增哪些记录、主要内容是什么；需要修改哪些记录、修改什么。不得解释、分析、列举证据、深入人物心理、判断特殊态度或输出JSON。不确定后台内容是否值得记录时可以先列入清单。正文剧情全部列入。

第二级负责定位已有记录、语义建模、拆分或合并事件、区分事件和认知、处理信息控制、关系与特殊态度，并输出统一变更批次。它不单独重做一次全量遗漏检查；只有在定位和关联过程中自然发现遗漏时补充。

多轮归档视为一段连续剧情，不按回合分别梳理。所有变更应绑定到本批最后一轮；来源捕获本身另有持久记录。原子提交成功后才推进 `lastArchivedTurn`。

每次成功自动归档同时创建一条 `memory.archive-coverage`，保存实际覆盖的起止回合、消息ID、工作流和批次。覆盖记录只证明该范围已被归档流程审视，不要求每一轮产生独立事件。

归档准备节点用代码计算冷却和保护范围，并通过 `routeFromOutput` 决定是否进入两级Agent节点。未达到条件时工作流直接跳过两级Agent与提交节点，不产生模型调用。延迟范围提交时由可信代码指定本批最后一轮的已有消息；公共运行时负责核对消息ID、回合和可见范围。

## 压缩

有效事件目录达到当前 `triggerEntryCount` 后，可以运行独立压缩工作流。默认目标90、触发150；每次成功压缩后两者各增加10。成功要求至少提交一条有效摘要且有效目录条数实际下降。

压缩Agent只读取有效事件目录，不读取完整事件、实体目录或隐蔽内容。它只能提出语义相关的 completed 记录分组。代码展开叶事件、派生时间范围和地点、检查重复覆盖与循环，再原子提交。

目标条数不是强制上限。没有合适分组时允许目录高于目标，不为了凑数合并无关事件。

压缩准备节点同样以代码路由控制后续Agent。有效目录未达到阈值且并非允许的手动触发时，规划和提交节点直接跳过。

## 维护

提交后由代码重建索引、有效投影、筛选面和诊断，不调用模型。所有摘要超限记录在下一次正常归档中交给第二级缩减。

不自动运行全库语义巡检。合并拆分、群体整理、模板或时间迁移、失效引用修复、撤回恢复等，只在用户指定任务和目标后运行手动维护工作流。维护使用 `expectedRevision`；冲突时重新读取，不强制覆盖。

## 手动回合范围修复与补充

用户可以从前端选择已完成的 `startTurn` 与 `endTurn`，并选择 `repair` 或 `supplement`。repair用于复核正文修订、失败归档或明显矛盾；supplement不预设旧记录错误，允许用户主动完善系统未发现的问题。可选focus只提供关注方向，不能扩大回合范围。

该工作流复用两级归档：第一级列客观清单，第二级完成限定语义建模。检查后没有领域变更也允许成功，但仍创建覆盖记录，表示当前消息修订下该范围已经由用户要求复核。事务绑定范围最后一轮，并保留实际读取消息的精确revision。

旧范围复核不会倒退 `lastArchivedTurn`。不连续范围先保存覆盖记录；只有覆盖区间与既有连续前沿接通时，代码才重新计算并推进连续归档位置。

前端提醒只使用“未完成归档覆盖”“归档依据的正文后来被修改”或“旧事务无法核验”等描述，不把现有记录自动定性为失效。提醒本身不启动工作流、不阻止下一轮；只有用户点击修复后，范围工作流才按声明阻止下一轮输入。
