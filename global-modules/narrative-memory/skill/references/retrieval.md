# 检索与组装

## 标准检索

调用方 Agent 用自然语言 Markdown 询问想了解的历史信息，允许模糊或需要判断的问题，例如“林月目前是否知道青鸦的真实身份”。调用方无需预先拆成实体、关系、事件或认知查询，也无需填写稳定 ID、内部查询字段、预算分配或判断相关记录是否存在。正文 Agent 把情景分析写入工作区文档，并在后面接着写查询清单；通过 `rp_call.textFile` 指定该文档。运行时读取文档全文作为 `textInput`，不解析标题、不提取清单，也不重复作为附件注入。其他调用方仍可通过 `rp_call.text` 直接提交查询文本；`text` 与 `textFile` 二选一。

`narrative-memory-retrieve` 从这份自然语言 Markdown 开始工作。检索 Agent 读取公共快照工作流生成的完整目录，结合调用方分析（如有）自主拆解检索方向、选择候选并在有效预算内分配查看量和返回量。分析中的猜测只是检索线索，不能当成记忆事实。依赖调用方分析的问题，如“有哪些被我忽略的历史线索”，以实际提供的分析为参照；未提供分析时，不能自行假定调用方想过什么。检索 Agent 在内部解析查询类别并输出结构化 JSON；结构化 JSON 不作为调用方接口。实体查询数量以有效预算为准；实体记录匹配后完整返回且不占信息记录预算。

检索 Agent 通过当前任务消息接收查询输入，包括调用方一并提供的分析；其余固定提示词、近期正文等按节点的上下文声明提供。实体、关系、有效事件、认知和知情群体的目录及有效预算由工作区文档交付。实际预算由代码根据持久设置和本次获准覆盖值解析；这里不另行维护一套固定条数。

有效事件目录中的摘要不是第二层目录。摘要记录自带全部 `coveredEventIds`；当摘要与询问有关时，检索Agent可以直接在同一次候选查看中读取需要的叶事件，不先发起一次“展开目录”。只有真正需要交给创作节点的叶事件才进入最终 matches。

偏实体匹配状态：

- `direct`：记录就是所问实体；
- `related`：名称不同，但很可能是别名、假名、误称或错别字对应的同一实体；
- `possible`：未找到所问实体，但该记录与问题明显相关。

偏信息匹配状态：

- `confirmed`：记录直接提供所问资料；不表示检索 Agent 已证实问题中的推断；
- `suggested`：存在相关迹象但不足以确认；
- `possible`：关联更弱的兜底记录；
- `not-found`：本次检索没有找到相关记录，不代表事情未发生、角色不知道或记忆库绝对不存在相关记录。

事件及其他信息、弹性结果和单项 `possible` 的有效预算均以本次调用输入为准。实体、关系和群体不占信息记录预算。不要给每条记录添加匹配说明。

检索 Agent 根据资料需要和相关性自主安排查询顺序，宽泛问题不必固定放在最后。可以在内部分析、形成假设并据初查结果进行至多一次弹性补查，但最终只选择已有记录，不能输出自己的剧情结论、推断理由、匹配说明、主观意见或行动建议。例如“青鸦可能是谁”可以引导身份相关的多方向检索，交付的是相关记录，不是检索 Agent 给出的身份结论。保留记录中的角色认知、不同视角、矛盾和不确定性，不把角色的怀疑提升为客观事实。输出中的 `query` 保留原询问，不复制分析全文，也不填入检索 Agent 的结论。

## 自定义预算单次检索

工作流仍声明必填的 `request` 文本输入；调用时使用 `text`，或用 `textFile` 指定调用方工作区内的 UTF-8 普通文件。文件全文在调用时读取并保存为本次输入，后续检索节点重试不会重新读取调用方文件。空白文件不能满足必填文本要求。获准自定义预算的调用节点可另行提供可选 `budget` 参数，例如：

```yaml
arguments:
  budget:
    entityQueryLimit: 40
    initialInspectLimit: 60
    supplementalInspectLimit: 15
    informationLimit: 45
    elasticInformationLimit: 10
    possiblePerQueryLimit: 3
```

持久设置决定默认预算；调用节点的静态工作流授权决定可提供的覆盖范围。`customBudgetInterfaceEnabled=false` 时忽略本次覆盖并使用持久默认值；启用后才应用获准覆盖值。公共调用入口拒绝未声明参数和错误基本类型，运行时仍以节点的查询预算与权限为最终上限。

## 目录与时间线快照

`narrative-memory-reference-snapshot` 是无 Agent 的确定性对外工作流。调用参数至少包含 `catalog` 或 `timeline` 之一；两者同时提供时在同一 `document-set` 中生成两份文档。

`catalog` 可限制 collection、record ID、record type 和白名单字段筛选。`entityIds` 可只生成单个或多个实体的目录：`entityMode: entry-only` 只返回这些实体的目录项；`entityMode: related-records` 还返回通过已声明索引直接关联的关系、事件、认知和知情群体目录项。`timeline` 当前使用 `mode: effective`，摘要替代其覆盖的叶事件，并可再按 ID 或白名单字段筛选。生成目录只交付当前调用者需要的 Markdown 表示，属于可重建快照。

检索、归档、范围修复、压缩与维护工作流需要目录或时间线时，都调用该工作流，不直接维护另一套目录实现。该入口允许代码、固定 `call` 节点和获准的 Agent 调用；基础工作流通常采用固定调用，动态 Agent 调用仅作为扩展点。

## 组装结果

代码验证ID、预算和匹配状态，去重并格式化。通用文档按每项查询组织：confirmed置顶，suggested放“相关记录”，possible放“可能有关的记录”；完全没有资料时写“未发现相关记录”。

限制视角名称由检索Agent解析为稳定ID，代码为每个目标另行生成视角文档。视角过滤只使用信息控制和知情群体，不依靠模型重新判断。

检索结果以 `document-set` 返回，包含 `DOCUMENTS.md`、通用记忆文档和按请求生成的限制视角文档。检索工作流不再隐式附加完整时间线；需要全局事件脉络的正文、导演或其他节点，应由工作流作者另外固定调用参考快照工作流的 `timeline` 参数。
