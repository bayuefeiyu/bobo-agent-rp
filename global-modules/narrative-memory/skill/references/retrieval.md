# 检索与组装

## 标准检索

调用方 Agent 先完成适合自身任务的分析，再输出自然语言 Markdown 查询清单。正文 Agent 可以分析当前情景；导演 Agent 可以分析整体剧情走向。查询清单不输出稳定 ID、purpose、topics、优先级或存在性判断，也不把需要检索 Agent 推理的结论当成查询目标。它应列出简单资料目标，例如实体、关系、事件、认知、知情群体或某一角色的有关认知记录。像“林月目前是否知道青鸦的真实身份”应拆成“林月有关青鸦身份的认知记录、青鸦身份相关记录及其知情范围”，最终结论由调用方 Agent 自己判断。

`narrative-memory-retrieve` 从这份自然语言 Markdown 开始工作。检索 Agent 读取由公共快照工作流生成的完整目录，在内部解析查询类别并输出结构化 JSON；结构化 JSON 不作为调用方接口。偏实体查询最多20项；实体记录本身是精选资料，匹配后完整返回且不占信息记录预算。

检索Agent接收世界观固定提示词、当前输入、近期正文、查询清单，以及实体、关系、有效事件、认知和知情群体的目录。实际预算由代码在每次检索开始前根据持久设置和本次获准覆盖值解析，并通过调用输入交付；这里不另行维护一套固定条数。

有效事件目录中的摘要不是第二层目录。摘要记录自带全部 `coveredEventIds`；当摘要与询问有关时，检索Agent可以直接在同一次候选查看中读取需要的叶事件，不先发起一次“展开目录”。只有真正需要交给创作节点的叶事件才进入最终 matches。

偏实体匹配状态：

- `direct`：记录就是所问实体；
- `related`：名称不同，但很可能是别名、假名、误称或错别字对应的同一实体；
- `possible`：未找到所问实体，但该记录与问题明显相关。

偏信息匹配状态：

- `confirmed`：记录明确回答；
- `suggested`：存在相关迹象但不足以确认；
- `possible`：关联更弱的兜底记录；
- `not-found`：没有找到记录。

事件及其他信息、弹性结果和单项 `possible` 的有效预算均以本次调用输入为准。实体、关系和群体不占信息记录预算。不要给每条记录添加匹配说明。

过于宽泛的请求在处理完具体请求后按剩余预算补充。偏推理请求不直接回答推理结论：例如“青鸦可能是谁”应检索该称呼及其近期行为有关的记录，而不是替创作Agent判定身份。

## 自定义预算单次检索

调用方始终通过必填的 `request` 文本输入提交自然语言 Markdown 查询清单。获准自定义预算的调用节点可另行提供可选 `budget` 参数，例如：

```yaml
arguments:
  budget:
    entityQueryLimit: 40
    initialInspectLimit: 60
    supplementalInspectLimit: 15
    informationLimit: 45
    elasticInformationLimit: 10
    possiblePerQueryLimit: 3
```

持久设置决定默认预算；调用节点的静态工作流授权决定可提供的覆盖范围。`customBudgetInterfaceEnabled=false` 时忽略本次覆盖并使用持久默认值；启用后才应用获准覆盖值。公共调用入口拒绝未声明参数和错误基本类型，运行时仍以节点的查询预算与权限为最终上限。

## 目录与时间线快照

`narrative-memory-reference-snapshot` 是无 Agent 的确定性对外工作流。调用参数至少包含 `catalog` 或 `timeline` 之一；两者同时提供时在同一 `document-set` 中生成两份文档。

`catalog` 可限制 collection、record ID、record type 和白名单字段筛选。`entityIds` 可只生成单个或多个实体的目录：`entityMode: entry-only` 只返回这些实体的目录项；`entityMode: related-records` 还返回通过已声明索引直接关联的关系、事件、认知和知情群体目录项。`timeline` 当前使用 `mode: effective`，摘要替代其覆盖的叶事件，并可再按 ID 或白名单字段筛选。生成目录只交付当前调用者需要的 Markdown 表示，属于可重建快照。

检索、归档、范围修复、压缩与维护工作流需要目录或时间线时，都调用该工作流，不直接维护另一套目录实现。该入口允许代码、固定 `call` 节点和获准的 Agent 调用；基础工作流通常采用固定调用，动态 Agent 调用仅作为扩展点。

## 组装结果

代码验证ID、预算和匹配状态，去重并格式化。通用文档按每项查询组织：confirmed置顶，suggested放“相关记录”，possible放“可能有关的记录”；完全没有资料时写“未发现相关记录”。

限制视角名称由检索Agent解析为稳定ID，代码为每个目标另行生成视角文档。视角过滤只使用信息控制和知情群体，不依靠模型重新判断。

检索结果以 `document-set` 返回，包含 `DOCUMENTS.md`、通用记忆文档和按请求生成的限制视角文档。检索工作流不再隐式附加完整时间线；需要全局事件脉络的正文、导演或其他节点，应由工作流作者另外固定调用参考快照工作流的 `timeline` 参数。
