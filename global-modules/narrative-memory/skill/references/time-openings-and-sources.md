# 时间、开局与来源适配

## 时间

每张卡必须在导入时填写 `config/time-system.json`，定义该卡的 `trueTime`格式、允许粒度、`sortValue`派生算法、歧义处理、示例和是否需要时间辅助记录。**声明与实现必须一起完成**：同一份规格要落到 `runtime/time-adapter.mjs`（导出 `timeRuleVersion`、`deriveSortValue(trueTime)`、`validateTrueTime(trueTime)`），模块自带的 `runtime/time-adapter.mjs` 在未配置时是抛错占位。只填 JSON 不实现适配器时，静态检查与游玩开场都不会报错，直到**第一次归档事件**在派生 `sortValue` 时失败（`narrative-memory time adapter is not configured for this card.`）——卡包校验器会核对两者是否一致。

无论现代日期还是“第N天”，事件都保留 `trueTime`和持久化 `sortValue`。自然语言时间可以模糊；trueTime要么精确到卡定义的小时、时辰或其他离散单位，要么降为整日，不能写“上午”“下午”“黄昏”。“大约十年前”可以为排序选择合理的近似日期，但展示时间仍保留“大约十年前”，且不得虚构小时。

改变排序算法需要更新 `timeRuleVersion`并执行显式迁移。兼容的年号、纪元等辅助映射可以在同一版本内更新；产生依赖它的新事件时，辅助记录与事件应在同一原子批次中提交。

## 开局

`config/openings/registry.json`登记每个开局自己的初始记录文件。只加载用户选择的开局。创作者可以完全预制初始记忆，不要求运行时Agent随机生成。

原卡主要角色的性格和行为指导是否迁入记忆必须与用户讨论；无论迁入与否都不得随意缩减作者原文。

## 其他模块来源

每个适配模块在 `config/archive-sources/` 下拥有一份配置，登记来源路径或命名视图、选择的字段、是否为可解析JSON、snapshot或per-turn历史模式、回合选择方式、捕获位置及可选标题。

来源还可以声明静态 `guidanceFile`。通用归档工作流准备某个来源时，必须把该说明作为该来源专属提示交给归档节点。提示只解释映射、知情范围、事实/认知类型和错误处理，不授予额外数据权限。若来源自身已经把条目标记为“确认归档”，归档 Agent 不得再次判断其价值。

JSON来源确定性转为YAML式结构；声明为JSON但解析失败时明确报错，不静默退为文本。非JSON来源按原文捕获。没有自定义标题时使用 `【<模块名>模块资料】`。

snapshot来源每轮在源模块更新后捕获，即使归档有冷却或保护回合；per-turn来源在能够稳定按回合读取时可保留在源模块，否则由记忆模块保存捕获历史。来源捕获只进入归档和调试上下文，不进入普通创作检索。

配置文件本身不授予跨模块读取权限。目标卡工作流必须为每个来源节点显式添加命名视图、能力和预算。为适配记忆而修改其他模块结构时，先说明风险并取得用户或创作者同意。
