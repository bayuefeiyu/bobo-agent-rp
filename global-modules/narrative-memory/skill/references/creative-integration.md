# 创作及其他工作流接入

模块提供两个彼此独立的 `module-external` 工作流，不把内部节点拼接进上级图：

```text
narrative-memory-reference-snapshot
  → 确定性组装目录、有效事件时间线或两者
  → 返回 document-set

narrative-memory-retrieve
  → 固定调用 reference-snapshot 取得完整目录
  → 检索 Agent 解析自然语言 Markdown 并匹配候选
  → 确定性组装通用及限制视角文档
  → 返回 document-set
```

## 调用方职责

情景分析、整体剧情分析和查询清单生成属于调用方 Agent 的任务，而不是记忆模块检索工作流的前置节点。正文、导演、编辑、角色模拟或后台系统都可按自己的任务分析资料并调用同一个检索入口。

调用方可以直接询问想了解的历史信息，包括模糊或需要判断的问题，无需先拆成记录类型、分配预算或判断是否存在记录。正文 Agent 将情景分析和其后的查询清单写在同一工作区 Markdown 文档中，通过 `rp_call.textFile` 指定该文件的相对路径，运行时把全文作为检索 Agent 的文本输入。其他调用方仍可通过 `text` 直接提交；两个参数不能同时提供。

检索 Agent 可利用分析判断查什么、如何分配预算，但调用方分析不是记忆事实。检索结果只交付已有记录及必要匹配状态，不输出检索 Agent 自己的剧情结论、理由或主观意见。例如可以直接问“林月目前是否知道青鸦的真实身份”，由检索 Agent 查找相关认知、事件和知情范围，最终判断由调用方完成。涉及“我遗漏了什么”的问题以一并提供的分析为参照，不要求额外写另一份分析。

这项约束应写入实际调用节点的作者提示词。模块工作流接口只说明输入语义，不替节点作者增加调用时机或使用策略。

## 进阶正文顺序

需要完整事件脉络的前景工作流，应在正文 Agent 启动前固定调用 `narrative-memory-reference-snapshot`，只请求 `timeline: {mode: effective}`，并把返回文档集放入该 Agent 的通用文档工作区。

正文 Agent 的工作顺序是：

1. 结合固定要求、最近正文、当前输入和有效事件时间线分析情景；
2. 将情景分析写入工作区文档，并在后面接着写自然语言 Markdown 查询清单；
3. 动态调用 `narrative-memory/narrative-memory-retrieve`，以 `textFile` 指定上述文档，并读取返回文档集；
4. 自行完成资料推理并形成初步剧情规划；
5. 只有此后才选读详细世界观、规则、指导、文风与格式资料；
6. 修正最终规划，创作并检查正文。

若上级 Agent 要自主调用检索或快照工作流，对应目标已设置 `agentCallable: true`，但上级节点仍必须把精确引用列入 `workflowCalls`。调用时机和用途完全由上级节点作者的提示词决定。

来源捕获、归档、压缩、范围修复和维护是 `module-internal` 工作流，只能由顶层工作流调用，同一模块内共享串行执行通道。它们需要目录或时间线时，在自己的完整工作流中固定调用参考快照入口。卡片作者应在所属功能模块内适配已登记的入口触发包装，并只在归档或关键状态一致性确有需要时，把包装工作流的 `trigger.blockNextTurnUntilReady` 设置为 `true`。
