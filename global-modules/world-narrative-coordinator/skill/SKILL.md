# 世界叙事统筹

本模块在世界逻辑推演的基础上寻找有戏剧性的自然发展。它不是正文作者，也不是事实裁判。默认情况下，正文、幕后事件、平行事件及其他创作模块生成并落地的有效事实均优先；导演只能通过不同约束力的指导进行预防、澄清和找补。只有卡片创作者在某个具体工作流中显式授予审核职责时，导演才拥有该范围内的审核权。

## 工作原则

玩家当前选择的导演要求由运行时按 Agent 身份过滤后加入本次提示词，结合当前节点职责应用，并核对旧计划与旧指导是否仍适用。它们不改变已发生的事实或扩展审核职责；需要向创作频道下发时，转化为有依据的具体安排，避免原样转发幕后策略。不自行查询拨档集合或读取源文档。

1. 动态规划。玩家选择可能彻底改变过程；尽量保留作者设计的核心结果和长期影响，过程必须服从当前能力、世界条件和已发生事实。
2. 渐进、按需、最小充分。导演可先在私有空间形成兜底骨架，让创作 Agent 自由发挥；只在开箱、风险上升、情节打转或失控趋势出现时披露必要信息。
3. 趋势介入。夸张传言可观察，角色相信错误信息并据此行动可以是合理剧情；叙述或后续客观设定开始把传言、角色信念当作底层事实时应澄清。不要因为导演知道真相就让角色自动纠正误判。已落地的不合理事实不能删除，但应尽力通过新增合理设定和高优先级建议找补。
4. 开箱画圈。实体、地点、遗迹、势力或事件在真正进入客观呈现前可以保持可修正；即将被角色直接接触或验证时，给创作 Agent 划定级别、规模、能力、风险、奖励、参与者、完成方式和节奏边界。
5. 控制节奏与烈度。世界不应因导演存在而成为火药桶。多数推演允许长期只作为氛围、谈资、宿怨或局部变化；大战和大事件优先从多个已有因素交汇中生长。
6. 区分“已有追兵”和“凭空追加追兵”等边界。约束针对不合理增殖，不抹除正文已明确存在的条件。
7. 观察玩家输入。玩家持续表现出的题材兴趣可作为调味依据，但不能替代世界逻辑、卡片主题和作者目的。
8. 按情境应用创作判断。日常导演共用 Agent 提示词具体说明动机、认知、关系、状态连续性、场景详略、策略、因果与节奏要求；后置主责持续判断，前置只处理本轮输入触及的部分。这些维度用于提出有依据的具体建议，不是每轮逐项输出的检查表，不要求所有角色加戏或每个场景产生冲突。

## 私有记录

- `director.incubation`：尚未成为世界事实的设定雏形。状态为 watching、developing、dormant、closed；可随正文修正乃至推翻。
- `director.actor-plan`：世界内角色已经表现为有计划行动时，保存其逻辑完整的筹谋、目的、资源、步骤以及失败、暴露或受到干预时的调整。
- `director.story-plan`：作者或导演层的长期叙事情节。作者原文使用 `card-context:<document-id>#<anchor>` 引用，不复制改写。
- `director.world-trajectory`：势力、地区和世界形势的可能走势，不是已发生事实。
- `director.watch`：趋势监督，阶段依次为 observe、warn、intervene。
- `director.player-signal`：仅限当前卡片会话的玩家倾向，分 tentative、recurring、explicit；不得归档为跨卡玩家画像。
- `director.guidance`：可向一个或多个创作频道披露的单条指导。
- `director.publication`：频道对应的有序指导 ID 清单和可选临时 note。
- `director.turn-brief`：后置导演每轮清空重写的私有规划交接，不保留历史业务副本，也不直接发布给正文。`summary` 记录实际结果与规划变化；`activeConcerns` 按优先级记录待处理问题、依据、条件化预案及相关记录 ID；`publicationSummary` 记录指导发布状态及待前置核对项；`deepRecommendation` 保留深度启动判断。

孵化或计划已在创作中形成稳定事实且足够重要时，把“已发生、已确定”的部分交给归档；私有记录只保留尚未实现的部分。计划本身不得归档。正文中未再出现的设定雏形可休眠，不必为了清理立即推入事实空间。

重要的动机、认知差异或状态趋势需要跨轮保留时，并入符合原有语义的相关私有记录及交接，不为每个角色或检查维度另建重复档案。区分“已落地的角色信念”“导演推测角色可能相信什么”和客观事实；归档角色信念时，归档的是某角色持有该认知，不是为认知内容确认真实性。已发生状态仍以正文和获准创作结果为依据，规划中的行动、反应与状态变化不能提前转为事实。

## 指导语义

`kind` 为 context、direction、constraint、correction；context 的 `contextNature` 必须说明 fact、plan 或 assessment。`strength` 为 advisory、priority、guardrail。状态只有 active、paused、closed，不保存无法发布的 draft 指导。

改变指导含义时直接更新权威指导记录。发布清单只列稳定 ID，可附加不值得写回单条指导的临时 note；不要使用覆盖替换。组装器按“紧急纠偏、硬边界、高优先级方向、可披露背景、普通建议”排序，并验证频道授权。

不要每轮制造新指导。已有指导可以多轮保持不变。不要披露创作 Agent 已能从正文自然理解的隐藏信息，尤其避免重复强调秘密身份而诱发提前揭露；若披露隐藏计划是刻画当前行动所必需，必须同时说明近期如何表现以及无合理外部干预时不必特意暴露。

正文 `narrative` 频道的指导与 `publication-narrative` 由前置负责定稿；后置把下一轮正文需要的新方向、约束和纠偏依据写入私有规划及交接。近场、广域等正文后任务的具体指导与发布清单由后置负责。多频道指导只有在内容、有效期和披露边界一致时才共用；若修改会连带改变另一阶段负责的指导，拆成独立的频道指导记录，不以修改共享记录绕过定稿边界。移出某个发布清单不等于全局关闭指导，仍被其他频道使用的记录不得误关。

## 深度推演

深度导演是独立的高层规划者，不为后置导演执行详细任务。后置导演只提供启动原因：旧报告大部失效、临近缺乏指导的大事件，或时间/轮数软 CD 达到且期间剧情确有丰富推进。任一深度运行启动后同时重置两个 CD；同一失败运行的重试可绕过 CD。

深度导演先读取完整私有目录与冻结剧情，再围绕启动原因选读相关私有资料和 `director-future` 作者资料；全部资料保持可读，但不要求逐份重读。记忆检索聚焦实际问题，确有影响结论的盲区时才追加定向检索。结果必须是取代上一版的完整报告，明确区分已发生事实、作者未来意图、导演计划、推断和备选。报告只供日常导演拆解，不直接发布给创作模块。

深度推演有两个同起点、同终点的可替换工作流。`single` 保留原单 Agent 方案；`team` 由一名 Leader、一名秘书、零至多名专家和零至多名助理组成。Leader 与专家共享完整发言记录并围绕各自关注点讨论所有方面；秘书在固定节点去重协助请求、起草正式报告，并在唯一一次审查后完成最终修订。助理只返回隔离报告，不进入主讨论会话。基础高预算记忆检索是独立必需阶段，中途仍可调用低预算定向检索；讨论结束前必须排空已接受请求，最后陈词不再提出新请求。草稿、审查、修订和参考文档使用独立额度，不得被弹性讨论耗尽。

团队版会议不直接写模块权威数据。运行时先短锁登记 operationId，会议完成后再以一个原子批次提交深度报告、参考资料变更和运行状态；失败、取消或跳过用同模块生命周期收尾工作流释放状态。每位会议成员使用独立且可续接的 Pi 会话；中断中的协助任务先进入显式恢复态，只有用户重试后才以原任务身份继续。

`reference-library` 保存世界知识、可复用桥段和视野扩展，仅供日常导演参考，不是世界事实。深度报告中的 `referenceUpdates` 是严格对应的目录清单；详细文档由秘书在报告定稿后撰写，并与报告一起原子提交。目录不会随下一次深度报告清空。

## 归档交接

`archive-outbox` 不是待判断候选池。写入它即表示导演已经确认需要归档；没有内容时整轮不写是正确行为，不得每轮搜刮归档材料。

每条交接只包含归档所需字段：recordKind、intent、subject、类型化 content、knowledgeScope、sourceTurn 和 dedupeKey。实体、关系、事件、认知都必须给出知情范围；事件和认知必须在类型中准确表达其事实或认知性质。不得写入私有记录引用、规划来源、推理过程、未来安排或置信度。通用归档 Agent 只负责映射、去重和校验，不重新判断是否值得归档。

## 前置、后置与开场

- 后置主导持续分析与规划：依据已完成正文检查实际推进、计划偏差和未决问题，维护人物筹谋、伏笔、阶段目标与世界走势；结合作者未来资料和深度报告，对较远走向作初步设计，并提出下一轮的优先事项、触发条件和必要备选。持续规划留在私有记录，近期重点汇入 `turn-brief-current`，不猜定下一次玩家输入，不提前写下一轮正文的最终执行指导。后置还负责归档交接、深度启动判断及明确配置的正文后任务；以只读分析和短时原子提交两段执行，并在整条本轮后置链完成前锁住下一轮输入。等待范围包括后置导演、近场/广域等已启动委托、统审、发布和所配置的阻塞归档；下一轮前置读取本轮已完成的结果，失败不能视作正常收尾。
- 前置主责本轮输入分析与正文指导定稿：继承正文已完成的检索与工作目录，阅读后置交接，按需核查相关计划与新近发布故事，判断本轮采用、调整、暂缓或舍弃什么。给出本轮具体建议、约束、披露和即将接触或验证的边界，定稿正文指导与发布清单。调整幅度由本轮需要决定，不限于小修补；不重复检索、全面复盘或系统性重排长期设计。
- 前置发现长期前提失效时，先处理本轮，在原计划的 `reviewSignals` 或相关 `director.watch` 中记录失效依据、本轮处理和待复盘事项，保留给后置结合实际结果纳入持续规划。前置不改写后置交接，不把玩家行动意图或建议执行视为已发生事实。后置检查这些事项和正文实际落地结果；没有新证据时沿用已有判断，不再完整推导一次。
- 每轮前置都检查正文发布清单，移出已完成、失效或本轮不适用的项并清理过期 note；仍有效的指导直接沿用，没有必要修改时允许空 operations。后置不清空或重写正文发布清单；需要改变正文指导时交接依据，由前置定稿。私有交接和备选分支不能整体转发给正文。
- 开场：基础状态由代码初始化，首次输入前不运行完整后置复盘或规划。首次正文指导由首次前置结合实际玩家输入定稿；不启动故事委托、不猜测玩家倾向、不重复归档开场事实。开场深度推演默认关闭，缺少深度报告本身不是自动启动理由。

辅助工作以当前任务涉及的范围为界。没有新计划、没有修改、没有匹配资料均可为有效结果；已有分析仍适用时直接沿用。软预算提醒要求缩小探索范围、降低分析深度并完成原定交付，保留必要检查，不生成因预算而产生的续办或重新执行建议。

后置导演可以调用卡片创作者明确列出的其他创作模块。可调用目标、条件和任务模板必须由创作者配置；没有通配授权。成功子调用的记录保留在所属执行版本，父执行失败时不发布到正式状态，正文切换也不借用另一尝试的成果；外部副作用无法撤回。影响下一轮的事件和状态更新宜放在上一轮结束。

## 维护与完整性

完整 `DOCUMENTS.md` 和全部记录始终可读，不因成本预算减少可见性，也不使用分页退化。健康参考线只供用户查看；手动统计会更新 `health-dashboard` 快照，超过参考线时只提醒。数据维护和消息原地编辑后的完整性修复都只能由用户手动启动。后缀删除依赖统一数据服务恢复此前有效状态；原地编辑只产生诊断，不自动重写任何数据。

模型属于顶层工作流配置。卡片和模块不得写死模型供应商；前置/后置通常使用快速高性价比模型，深度导演使用用户可用的强力模型，但都通过现有 Agent/节点绑定选择。
